## What moved

**BOT — B7, the continuous paper run. BUILT, TESTED, RUN.**

`src/bot_stack_paper_run.py` wires the three existing pieces into one loop:
`base_entry_b3.py`'s signal -> `risk_state_engine.py`'s decision -> (if the
signal fires and BOTH the risk_state_engine's `trade_permission` and
`capital_protection`'s gate allow it) `order_path.py`'s real order machinery
against `simulated_broker.py`. Every session gets exactly one row logged to
the new `research/forward_validation/bot_stack_paper_log.jsonl`, whatever
happened — signal, no-signal, blocked, filled — not just the sessions that
fired a signal. That file split from `bot_stack_forward_log.jsonl` (the
STATISTICAL log) IS the two-clocks rule made concrete: this file only ever
submits real orders through the real order path; it is never compared
against the statistical numbers, even on the same session. 14 new tests
(`tests/test_bot_stack_paper_run.py`); full suite 372/372.

Five choices this file makes explicit rather than deciding silently (full
reasoning in the file's own header docstring):
1. **B7 gets its own execution anchor (2026-09-08), separate from the
   statistical log's forward-only anchor (2026-09-14).** B7 isn't making a
   statistical claim, so it doesn't need to wait for genuinely-forward data —
   it exists to prove the order-path loop runs every session without
   skipping one, which only needs a starting point, not a forward boundary.
   The anchor is written to disk on first run so a later cycle can't
   silently redefine it.
2. A fresh `SimulatedBroker()` per session — no cross-session broker state
   assumed yet (no carried position, no in-flight order spanning sessions).
   Parked as a real design question for later, not decided silently.
3. The order is built from B3's own raw signal (unconditioned stop/target).
   B2's decision contributes `size_multiplier` and `trade_permission` only —
   not a substitute stop/target, which stays `bot_forward_log.py`'s
   statistical comparison to answer, not a live order decision.
4. Bookkeeping P&L (feeds `capital_protection`'s equity/peak/daily-loss
   gate) is resolved by walking the session's own already-elapsed bars
   forward from the fill — mechanically identical to
   `bot_forward_log.py`'s exit logic but deliberately re-implemented locally
   rather than imported, so the two clocks' code stays visibly separate, not
   just their file names.
5. Dollar P&L is GROSS — no commission/slippage-beyond-fill cost model.
   MNQ_MULTIPLIER=$2/point matches `backtest.py`'s own documented figure for
   Micro NQ. Inventing an MNQ commission number here would be exactly the
   kind of fabricated data the standing rules forbid; a costed number is
   future work once real execution costs exist.
