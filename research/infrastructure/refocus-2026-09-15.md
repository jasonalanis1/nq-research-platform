# Queue item — Refocus: one job, less overhead

**From:** Jason, September 15th, 2026
**Type:** Standing direction. Supersedes the "push this as fast as possible"
direction from September 14th.

---

## 1. No profit deadline sits on this project — standing rule

Any date by which I need trading income is **not** an input to research
scheduling, promotion decisions, or the bot roadmap. If I ever state one, treat
it as a flag that I am under pressure, not as a constraint to plan around, and
say so.

Reason: every gate in this system exists to make self-deception expensive. A
profit deadline is the single most reliable way to make bending one feel
justified. The account is money I can afford to lose; nothing about the pace of
the research changes that.

This rule is mine to set and mine alone to reverse, in writing.

## 2. Cadence back to daytime 2-hour

Revert the 24-hour / 12-cycles-a-day acceleration. Back to daytime 2-hour
cycles.

Reason, stated plainly: the acceleration window produced 16 fills from a
placeholder that proves no edge, 25 screen survivors of which 18 flagged placebo
RED, seven operational defects including a contaminated live execution journal,
and zero directional candidates. Throughput doubled; progress did not. The error
rate did.

Related: **a cycle with no real queue item closes early and says so.** Open
budget is not a reason to find work. Batch screening is not filler.

## 3. Freeze magnitude research

No new magnitude hypotheses, no new batch screens, until the directional
question is answered. Magnitude is not what blocks the bot. Existing validated
facts stay where they are; the Risk/State Engine keeps using them.

The 25 batch-screen survivors stay shelved and unworked. Before any of them is
ever drawn, the 72% placebo-RED rate needs a real explanation, not a logged
note.

## 4. Open a reserved directional lane — 20 trials, hard stop

- Directional candidates get their own slot count that magnitude cannot
  outrank. The current queue ranks by strength, magnitude always wins, so the
  entry slot stays empty by construction. That is a sorting rule, not a
  research finding, and it ends here.
- **Sourced only from non-state ideas** — not from the Idea Factory's state
  library. 87 directional nulls and ~9,910 state combinations say that space is
  exhausted. New candidates must come from mechanism, calendar, or structure.
- **First candidate: the overnight-versus-intraday return split.** Full Scope
  v4 confirms it has never been tested as a hypothesis, only as an integrity
  check. It is a published effect with a non-behavioral mechanism.
- **Hard stop at 20 trials.** Pre-committed now, while it costs nothing: if 20
  trials return null, direction is closed by evidence. The project then becomes
  a decision about what Tony is instead of a directional bot — my call, not an
  automated one.

## 5. Retire the console

Remove it. `src/generate_console_state.py`, the push sequence, the artifact, the
`_console_state.json` state doc. It is overhead that nothing depends on, and the
session report already carries every number it showed.

Do not maintain it, do not port it, do not rebuild a replacement.

## 6. Overhead cuts

- **Full Scope: weekly or on request only.** Not per-window. Auditing 19
  commits and 9,000 changed lines each time is expensive and three versions in
  four days is not a control, it's a cost.
- **Report actual usage.** Each daily wrap states cycles run and minutes used.
  I want to see the number, not estimate it.

## 7. Operational gaps — fix these

Five gaps, from an outside read of the operations layer. Ordered by payoff.

**7.1 The busy-work alarm measures activity, not discovery.** It fires after
three cycles with no ledger movement — but batch screening moved 25 rows while
discovering close to nothing, so the guard passed during exactly the failure it
exists to catch. Fix: redefine "movement" as a candidate **changing stage**, not
a row changing. Shelf additions count as zero. One-line change, biggest payoff.

**7.2 Errors are found incidentally, by whoever happens to be looking.**
Duplicate triggers found while closing out the day. The 40-vs-20 sample size
carried across multiple documents before anyone checked. Three reporting bugs
found while building the reporter. Fix: one **weekly verification cycle** whose
only job is checking Tony against itself — numbers in the docs against numbers
in the code, registry counts against actual files, scheduled triggers against
what's booked. No new research in that cycle.

**7.3 No separation between test and production.** A test wrote four synthetic
fills into the live execution journal. The conftest fixture patched that
specific leak; the general problem stands. Fix: production paths refuse writes
unless an explicit production flag is set, so a test cannot reach them by
default. Audit every path the code writes to and report which are protected and
which aren't.

**7.4 The system audits itself.** Busy-work detection, shelf alerts, the
applicability rule — all run inside Tony's cycles, and Tony writes the report
about them. Nothing external checks it. Two fixes: (a) factual claims in reports
cite file and line so I can verify rather than trust; (b) I paste project state
to an outside model on a cadence, not only when something feels wrong.

**7.5 Single point of failure.** One person, one device bridge that drops, one
persistent session. Mostly accepted. One thing worth confirming: the repo is
actually pushing to GitHub, so the work survives a dead machine. Verify and
report.
