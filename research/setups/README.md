# setups/

The real, refined definitions of the setups Jason actually trades —
distinct from `../experiments/`, which records what happened when a
setup got tested. This folder answers "what IS the setup," in plain
language, kept in sync with whatever `src/detect_setups.py` (or its
successors) actually implements in code.

One file per setup. As definitions get refined through conversation and
testing, update the file in place (unlike experiment results, a setup
DEFINITION is meant to evolve — it's not "ground truth output" the way a
backtest result is).
